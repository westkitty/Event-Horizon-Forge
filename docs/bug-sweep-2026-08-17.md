## Confirmed bugs and repairs

### BUG-001 — Persistent Controls synthetic shortcuts could crash before acting
- Status: fixed and browser-verified
- Severity: high
- Area: `src/interaction/InputRouter.ts` / `src/main.ts` interaction
- Evidence: Persistent Controls dispatch keyboard events on `window`. `isUiControl()` cast any
  `EventTarget` to `HTMLElement` and unconditionally called `.closest()`, which throws for `Window`.
  Chromium reproduction produced `TypeError: el.closest is not a function` and no Pause action.
- Repair: make text/UI target predicates real DOM type guards (`HTMLElement` / `Element`) instead of
  unchecked casts.
- Validation: exact repaired router exercised in Chromium; synthetic `Window` KeyK routes one Pause
  action with zero page errors. Integrated Overlay + InputRouter harness routes Pause/Fork/Swap/Clean.

### BUG-002 — Holding Shift+H could oscillate Persistent Controls through OS key repeat
- Status: fixed and browser-verified
- Severity: medium
- Area: `src/interaction/InputRouter.ts`
- Evidence: the Shift+H branch ran before the generic pressed-key suppression and did not inspect
  `KeyboardEvent.repeat`; Chromium reproduction counted two toggles from one initial keydown plus one
  repeat event.
- Repair: ignore repeat keydowns for the Shift+H accessibility toggle.
- Validation: repaired Chromium harness records exactly one toggle for the same event sequence.

### BUG-003 — Escalating a one-finger manipulation to two-finger camera control left App manipulation stale
- Status: fixed and browser-verified
- Severity: high
- Area: `src/interaction/InputRouter.ts`
- Evidence: after a body drag crossed the manipulation threshold, a second touch replaced the router
  phase with `touchCamera` without sending the existing non-committing cancellation signal. Chromium
  reproduction logged manipulation start/move and no Escape/cancel transition.
- Repair: before entering the two-touch camera phase, active manipulation now invokes the existing
  App cancellation path.
- Validation: repaired Chromium harness logs manipulation start followed by Escape and never emits
  manipulate-end/release for the interrupted gesture.

### BUG-004 — Back/Forward Cache restore could lose persistent-control and reduced-motion listeners
- Status: fixed and browser-verified
- Severity: medium
- Area: `src/main.ts`
- Evidence: the page-lifetime listeners were removed on every `pagehide`, including
  `PageTransitionEvent.persisted === true` where the page is frozen for BFCache rather than destroyed.
  A Chromium harness using the actual transpiled entrypoint showed the persistent toggle stopped
  responding after a persisted pagehide.
- Repair: preserve page-lifetime listeners and the debug sampling timer when `pagehide.persisted` is
  true; cleanup remains for a real page destruction path.
- Validation: the same harness fails on the baseline lifecycle logic and passes after the repair.

sweep does not mutate that file.

`bun run test`, `bun run typecheck`, `bun run build`, and `bun run test:e2e`. The exact changed browser
modules are runtime-verified here, but that is not a substitute for the complete Vite/WebGPU app gate.
